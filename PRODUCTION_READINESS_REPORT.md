## 3. PostgreSQL RLS & Supabase Connection Audit

### Audit Checks:
- Inspected environment variables for Supabase configuration:
  - `DATABASE_URL`: `None`
  - `SUPABASE_URL`: `None`
  - `SUPABASE_SERVICE_KEY`: `NOT SET`
  - `.env` file: `False`
- Checked local PostgreSQL services:
  - `Get-Service *postgres*`: No service installed.

### Architecture Analysis of RLS in the Backend:
In `backend/app/database.py`, the backend connects via SQLAlchemy asyncpg pooler. 
- The policies in `backend/sql/rls_policies.sql` use `auth.uid() = user_id`.
- When FastAPI connects directly via pooler as the database owner/superuser, PostgreSQL bypasses RLS by default.
- For non-superuser roles, Supabase RLS expects request context (`request.jwt.claim.sub`). The FastAPI backend does not set `SET LOCAL` on each pooled connection.
- **Defense-in-Depth Implementation:** All queries in `papers.py`, `questions.py`, `analysis.py`, etc., strictly enforce `WHERE user_id == current_user.id` at the SQLAlchemy application layer.
- Cross-user isolation was verified via automated integration tests (`test_cross_user_isolation.py` and `test_4_cross_user_isolation` in `test_security_acceptance.py`).

**Status:** **APPLICATION-LAYER ISOLATION VERIFIED; LIVE SUPABASE RLS UNTESTED DUE TO ABSENCE OF SUPABASE CREDENTIALS.**

- **Scenario:** Ephemeral RAM session keys expire after 120 minutes of inactivity or upon explicit logout.

## 10. Frontend-to-Backend API Integration Audit

During the audit, all API routes between frontend and backend were tested and several critical discrepancies were remediated:

### Issues Discovered & Fixed:
1. **`Predictions.tsx` Field Mismatches:**
   - Frontend expected `topic`, `subtopic`, `confidence`, `reasoning`, `evidence`.
   - Backend returned `topic_name`, `subtopic_name`, `calibrated_confidence`, `explanation`, `historical_evidence`.
   - Remediated: Aligned `types/index.ts` and `Predictions.tsx` to handle both canonical backend schemas and legacy aliases.
2. **`Predictions.tsx` Response Envelope:**
   - Backend `/predictions` returned `{ predictions: [...], total, ... }`. Frontend expected array.
   - Remediated: `predictionsApi.list` unwraps `res.data.predictions || []`.
3. **`MockTests.tsx` Case Sensitivity Bug:**
   - Backend returned `question_type: "MCQ"`.
   - Frontend evaluated `q.question_type === 'mcq'`, causing option buttons and TITA inputs not to render.
   - Remediated: Made comparisons case-insensitive (`q.question_type.toLowerCase() === 'mcq'`).
4. **`authApi.register` Token Handling:**
   - Backend `/auth/register` returned `TokenResponse`.
   - Frontend treated it as `User` directly and missed storing `access_token` in `localStorage`.
   - Remediated: Updated `api.ts` to store `access_token` and return `res.data.user`.

### Full Integration Test Execution:
